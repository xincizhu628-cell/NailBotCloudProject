# NailBot 正式运营 TODO

这是一份“从现在能演示”到“真的能营业”的优先级清单。

## 第一阶段：先让网站稳定在线

- 把当前代码部署到云服务器。
- 用 `.env.production.example` 创建正式 `.env`。
- 确认 `https://nailbotau.com` 可以访问主站和后台。
- 用进程管理工具保证服务自动重启。
- 每天自动备份 `data/nail_studio.db`。

## 第二阶段：把数据库和图片搬出本机

- 将 SQLite 迁移到托管 PostgreSQL。
- 将商品图、模板图、活动图迁移到 Cloudflare R2 或 S3。
- 给列表页加缩略图字段，减少加载压力。
- 后端接口支持分页、搜索、分类筛选，而不是一次返回全部高清内容。

## 第三阶段：支付真正闭环

- Square production payment 已可配置，但还需要 webhook。
- 新增 `payments`、`payment_webhook_events`、`refunds` 表。
- 支付成功后自动更新订单状态。
- 支付失败、取消、退款都要在订单里有状态。
- 自提订单要生成取货码。

## 第四阶段：设备和厂家接口

需要和厂家确认至少这些接口：

- 获取打印码
- 获取取货码
- 获取设备状态
- 获取设备打印记录
- 获取打印任务状态
- 获取穿戴甲销售记录和订单取货情况
- 远程出货
- 订单退款
- 鉴权方式

接口正式接入前，可以保留当前占位逻辑，但不要把模拟远程出货当成最终方案。

## 第五阶段：账号和安全

- 管理员后台加角色权限。
- 用户验证码发送接入正式邮箱/短信供应商。
- 登录 session 设置过期时间、刷新策略。
- 上传图片限制格式和大小。
- 后台敏感接口加鉴权。
- 记录关键操作日志。

## 第六阶段：体验和性能

- 商品列表、模板列表全部分页/懒加载。
- 图片统一生成缩略图。
- 页面弹窗独立挂载，不影响主页面列表渲染。
- 画布保存使用草稿接口，不再混入模板库。
- AI 生成任务做排队状态，不让用户一直等白屏。

## 最小上线包

如果只想先小范围试运营，最小上线包是：

- `server.js`
- `package.json`
- `index.html`
- `admin.html`
- 其它 `.html` 页面
- `app.js`
- `styles.css`
- `services/`
- `database/`
- `data/nail_studio.db`
- `assets/`
- `.env` 生产环境版本

不要包含：

- `.git/`
- `.env.example` 以外的真实密钥样本
- `.tmp_*`
- `__pycache__`
- 本地截图和剪贴板图片
